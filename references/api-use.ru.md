# API: локальная подготовка и чтение ответов

Используйте Python 3.10+; внешние пакеты Python не требуются. Скрипты создают и читают локальные файлы. Они никогда не обращаются к провайдеру, не читают ключ и не вызывают расходов на API. В приведённых ниже командах используется синтаксис оболочки Bash/POSIX. Запускайте их из отдельного рабочего каталога; создаваемые файлы не могут перезаписать этот пакет или входной файл.

## Подготовка

Задайте в `BEFOREWORD_DIR` путь к каталогу распакованного пакета, а в `BEFOREWORD_MODEL` — модель, доступную для выбранной конечной точки. Эти два имени переменных приняты в данном пакете. Сохраните запрос в файле `input.txt` в кодировке UTF-8; интерфейс командной строки сохраняет окончания строк, пробельные символы и Unicode без нормализации. Параметр `--language` выбирает язык инструкции, а не обязательный язык ответа.

Начните в корне распакованного репозитория. Эти команды создают отдельную временную рабочую папку и запрашивают идентификатор модели; обращения к провайдеру нет:

```bash
BEFOREWORD_DIR="$(pwd)"
BEFOREWORD_WORK="$(mktemp -d)"
cd "$BEFOREWORD_WORK"
printf '%s\n' 'Разбери написанную фразу: Я понимаю.' > input.txt
printf 'Идентификатор доступной модели: '
read -r BEFOREWORD_MODEL
test -n "$BEFOREWORD_MODEL" || exit 1
```

```bash
python3 "$BEFOREWORD_DIR/scripts/build_payload.py" openai \
  --model "$BEFOREWORD_MODEL" --language ru \
  --input-file input.txt --output request.json
```

Аргументы для выбора провайдера: `openai`, `anthropic`, `gemini`, `grok`, `deepseek`, `qwen`, `mistral`. Параметр `--max-tokens` используется только для Anthropic (по умолчанию — 2048); выберите поддерживаемое значение с учётом задачи и модели. Настройки сэмплирования, рассуждения и инструментов автоматически не добавляются. Форматировщик принимает пустой текст без изменений; удалённый API может отклонить пустой запрос.

## Осознанная отправка

В `api.json` указаны методы, конечные точки, заголовки и обозначения переменных для ключей. Сформированное тело JSON — это ещё не полный HTTP-запрос. Перед отправкой прочитайте запись о выбранном провайдере. Получите и настройте учётные данные средствами самого провайдера для управления аккаунтом; не помещайте их в HTML-руководство, инструкцию, входной текст, историю или примеры ответов, которыми делитесь.

Пример для OpenAI при условии, что `OPENAI_API_KEY` уже настроен локально:

```bash
curl --silent --show-error --request POST \
  'https://api.openai.com/v1/responses' \
  --header "Authorization: Bearer $OPENAI_API_KEY" \
  --header 'Content-Type: application/json' \
  --data-binary @request.json \
  --dump-header response.headers --output response.json \
  --write-out '%{http_code}\n'
```

При запуске эта команда отправляет текст провайдеру и может привести к расходам. Для другого провайдера замените и конечную точку, и заголовки по данным из `api.json`; одной замены имени хоста недостаточно. Для Qwen необходимо указать в `QWEN_CHAT_ENDPOINT` полную конечную точку, совместимую с регионом и рабочим пространством; пакет не подставляет предполагаемое значение по умолчанию. Anthropic использует `x-api-key` и `anthropic-version`, а заголовок рабочего пространства — только там, где он требуется. Gemini использует `x-goog-api-key`.

Прежде чем интерпретировать тело ответа, проверьте HTTP-статус. При 400/404 проверьте поля, конечную точку, модель и поддерживаемые настройки; при 401/403 — доступ и регион; при 429 — ограничения частоты запросов у провайдера и заголовок `Retry-After`, если он присутствует. Сохраните тело ответа с ошибкой. Не повторяйте платные запросы бесконечно и не принимайте ошибки передачи за ответы модели. Для ответа не в формате JSON или потокового ответа нужен собственный парсер провайдера.

## Чтение сохранённого ответа

```bash
python3 "$BEFOREWORD_DIR/scripts/extract_response.py" openai \
  --response-file response.json --output answer.json
```

Скрипт извлечения обрабатывает семь форматов текстовых ответов без потоковой передачи. Он сохраняет `text_parts`, исходные значения `status` и `finish_reason` от провайдера, доступные поля расхода ресурсов и ошибок, а также указывает типы пропущенных блоков рассуждения, инструментов и нетекстовых блоков. Поле `text` объединяет выбранные части видимого текста без добавления разделителей; сохраняйте `text_parts` и исходный ответ, чтобы не потерять точные границы частей. Поле `phase` сообщений OpenAI/Grok остаётся привязанным к каждой части: комментарий не помечается как окончательный ответ. Для Chat Completions по умолчанию выбирается вариант с индексом 0 (`--choice-index` позволяет выбрать другой).

Пустой текстовый результат не означает успешного чтения. Проверьте отказы, пропущенные блоки, статус и причину завершения. Значения `incomplete`, `max_tokens` или `length` указывают на возможное усечение результата; прежде чем оценивать его, изучите исходный ответ провайдера. Скрипт извлечения не превращает частичный ответ или ответ с ошибкой в завершённый ответ. Он не обрабатывает события SSE и ответы Gemini `generateContent`.

## Продолжение текстового диалога

Создайте `history.json` как упорядоченный JSON-массив с точными текстами предыдущих сообщений, затем передайте его вместе со следующим входным текстом:

```json
[
  {"role": "user", "content": "Earlier request, preserved exactly."},
  {"role": "assistant", "content": "Earlier visible answer, preserved exactly."}
]
```

```bash
python3 "$BEFOREWORD_DIR/scripts/build_payload.py" gemini \
  --model "$BEFOREWORD_MODEL" --language ru \
  --history history.json --input-file next-input.txt \
  --output next-request.json
```

Во всех семи форматах beforeword отправляется заново с каждым запросом. Для Gemini эти текстовые сообщения преобразуются в документированные шаги `user_input`/`model_output`. Файлы не используют серверные идентификаторы предыдущих ответов; там, где это поддерживает выбранный адаптер, используется `store=false`. Этот флаг не описывает все правила обработки данных у провайдеров.

Этот переносимый формат хранит только видимый текст. Он не обеспечивает экспорт без потерь для рассуждений, подписанных блоков, инструментов, цитат, изображений или аудио в собственном формате провайдера. Не удаляйте такие элементы из диалога с инструментами или агентом в собственном формате провайдера, представляя результат как эквивалентное продолжение; сохраняйте исходные объекты ответов и следуйте документации провайдера о продолжении диалога. Длинная история может превысить контекст модели; неявное сокращение не выполняется.

## Оценка

Сохраните точные файлы запросов и ответов, идентификатор модели, возвращённый провайдером, конечную точку, версию инструкции и настройки генерации. Примените `evaluation.md` к фактическому видимому ответу. Локальные проверки JSON и кодировки устанавливают только поведение форматирования; они не устанавливают соблюдение инструкции или beforeword как факт. Запустите локальные проверки командой:

```bash
python3 "$BEFOREWORD_DIR/scripts/test_payload.py"
```

Первичная документация по запросам и ответам перечислена для каждого провайдера в `api.json`; она прочитана для пакета от 2026-10-01 UTC. Доступность и ограничения конкретных моделей остаются за пределами этих файлов.
