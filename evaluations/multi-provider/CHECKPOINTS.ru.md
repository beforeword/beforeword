# beforeword · продолжение испытаний без слепых повторов

[English](CHECKPOINTS.md) · [Запускатор и оценка](README.md)

`checkpoint.py` сохраняет план запроса до его отправки и каждый полученный результат в локальную базу SQLite. Это дополнение к `run.py`, а не снятие лимитов ChatGPT, покупка кредитов или подтверждение списаний. Реальные обращения требуют явного `--execute` и отдельно настроенного доступа к провайдеру.

## Подготовка, запуск, продолжение

Из корня репозитория — подготовка двух заданий без обращений к модели и без записи контрольного файла:

```bash
python3 evaluations/multi-provider/checkpoint.py --model PROVIDER/MODEL
```

Вместо `PROVIDER/MODEL` нужен существующий поддерживаемый маршрут. Явный запуск, который может потребовать оплаты:

```bash
python3 evaluations/multi-provider/checkpoint.py --execute --model PROVIDER/MODEL --state results/baseline.sqlite3
```

После прерывания повтори те же параметры, добавив `--resume`:

```bash
python3 evaluations/multi-provider/checkpoint.py --execute --resume --model PROVIDER/MODEL --state results/baseline.sqlite3
```

По умолчанию выбираются два задания на маршрут. `--all` выбирает весь набор, `--limit N` — первые N заданий. Произвольное ограничение может оставить пару a/b неполной; такой запуск нельзя выдавать за полную парную проверку.

Параметры `--dataset`, `--instruction-file`, `--timeout`, `--max-tokens` и `--temperature` соответствуют исходному запускатору. Для русской редакции 1.3.6 подготовка выглядит так:

```bash
python3 evaluations/multi-provider/checkpoint.py \
  --dataset evaluations/instruction-1.3.6/samples.ru.jsonl \
  --instruction-file evaluations/instruction-1.3.6/core.ru.txt \
  --model PROVIDER/MODEL
```

Только добавление `--execute --state results/candidate-ru.sqlite3` разрешает реальные запросы. Для базового варианта, 1.3.5 и 1.3.6 нужны отдельные контрольные файлы. Для сравнения сохраняются одинаковые задания и параметры. Приведённые команды не означают, что сравнение уже проведено.

## Что сохраняется

`pending` — отметки о начале ещё нет; задание допускается к первой попытке. `started` — отметка записана, но итог отсутствует; такой запрос **не повторяется автоматически**. `response_received` — записан непустой текст ответа; повтор пропускается. `request_failed` — записана ошибка или неподдерживаемый ответ; повтор также пропускается. Ошибка не доказывает отсутствие списания.

При первой записанной ошибке очередь останавливается, чтобы не отправлять остальные задания при том же исчерпанном лимите или ошибке доступа. Следующий явный запуск с `--resume` может выполнить ещё не начатые задания. Ошибочный и неопределённый запросы он не повторяет.

Сбой между отметкой `started` и фактической отправкой тоже оставляет неопределённый исход. Это осторожное ограничение: часть заданий может остаться без ответа, зато отсутствие результата не превращается в разрешение повторно потратить ресурс.

План содержит исходные сообщения, критерии, инструкцию, выбранные задания и модели, параметры, контрольную сумму набора и исходников обоих запускаторов. Изменение плана, исчезновение строки или повреждение записи блокирует продолжение до запросов. Контрольная сумма выявляет несоответствие, но не удостоверяет происхождение или неподдельность. Настройки и развёртывания самого провайдера могут измениться между запусками.

Отдельная блокировка SQLite не допускает одновременной работы двух процессов с тем же контрольным файлом и освобождается при завершении процесса. Используй локальный диск, не сетевую или синхронизируемую папку. Пока запуск работает, не удаляй базу и файлы блокировки. Копии базы независимы: блокировка одной не защищает другую.

Оба запускатора явно передают LiteLLM `num_retries=0` и сохраняют это в параметрах. Это не гарантия отсутствия повторов внутри шлюза или провайдера, не подтверждение оплаты и не гарантия однократного внешнего выполнения.

## Просмотр и выгрузка без обращений к моделям

```bash
python3 evaluations/multi-provider/checkpoint.py --state results/baseline.sqlite3 --status
python3 evaluations/multi-provider/checkpoint.py --state results/baseline.sqlite3 --export-jsonl results/baseline.jsonl
```

Выгрузка создаёт новый JSONL и обязательный соседний файл `baseline.jsonl.manifest.json` с охватом: сколько заданий запланировано, не начато, осталось неопределённым, завершилось ошибкой или получением текста. Существующие файлы не перезаписываются. Оба файла нужно хранить вместе: полученная часть ответов не равна всему набору.

JSONL содержит только итоговые записи и совместим с `score.py`. Если итоговых записей пока нет, выгрузка пуста и ещё не подходит для оценки. Неопределённый исход не подменяется вымышленным ответом или оценкой. Решения по критериям по-прежнему вносит отдельный проверяющий; автоматических оценок качества моделей здесь нет.

Старый JSONL от `run.py` нельзя продолжить этим инструментом: в нём нет предварительных отметок отправки. Контрольные файлы содержат инструкции, задания и ответы; не публикуй частные данные. `/results/` и рабочие файлы SQLite исключены из обычного добавления в Git, но это не защищает от принудительного добавления или загрузки в другой сервис.

## Локальные проверки

```bash
python3 evaluations/multi-provider/test_runner_contract.py
python3 evaluations/multi-provider/test_checkpoint.py
python3 -O evaluations/multi-provider/test_runner_contract.py
python3 -O evaluations/multi-provider/test_checkpoint.py
```

Проверяются синтетические ответы, точность текста, параметры повторов, прерывание процесса, продолжение, блокировка, изменения плана, повреждённые записи и охват выгрузки. Это проверки программы, не результаты реальных моделей, установки в приложении или аудита списаний.
